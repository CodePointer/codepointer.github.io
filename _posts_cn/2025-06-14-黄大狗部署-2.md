## 前言 Introduction

我的APP主要包含三个部分的内容：数据库（Database），后端（Backend），前端（Frontend）。这三个部分都需要部署到Azure上，同时价格需要尽可能低廉，能白嫖就要白嫖。

对于数据库部分，我准备使用的方案是`Azure Database for PostgreSQL Flexible Server`。

下面的部分假设已经注册了Azure的账户，已经可以登录到Azure Portal。

## Service Creation

在搜索框里搜索 `PostgreSQL`，找到`Azure Database for PostgreSQL Flexible Server`，然后点击 Create 并填写相应的信息。下面我会一项项说明每项的含义以及我填写的内容。

> 当搜索 *PostgreSQL* 时，你会看到两个PostgreSQL的内容：Azure Database for PostgreSQL Server 和 Azure Database for PostgreSQL Flexible Server。前者是传统的PostgreSQL Server，后者是新的Flexible Server。选择新的这个就行。
{: .prompt-tip }


### Basics

- Project details, Subscription & Resource group: 创建的这个Service的分组。Subscription应该和Azure的付费有关，而Resource group则是自己设置的一个分组，用来区分不同的用途。比如，我的APP会包括多个Service（Database，Backend和Frontend），那我就会在这里创建一个新的Resource group把这三个Service放在一起。

- Server details:
  - Server name: 应用的名字。起一个自己需要的名字即可。
  - Region：服务器所在的位置。考虑到我这个应用主要使用的区域可能是中国和澳大利亚，因此我选择了东南亚 (Southeast Asia) 作为服务器的位置。
  - PostgreSQL version：PostgreSQL的版本。选择和自己本地版本相同的即可。
  - Workload type：负载类型。我选择了 Development。
  - Compute + Storage：此处可能需要选`Configure server`进去更改。本着尽可能便宜的原则，我选择了`Burstable B1ms`。
  - Availability zone: No preference

- High availability: 选择了Disabled，穷鬼套只能选这个

- Authentication：
  - Authentication method: 选择了 `PostgreSQL and Microsoft Entra anthentication`。
  - Microsoft Entra administrator：这个应该会自动选择成当前的账户。
  - Administrator login: 此处会要求填写用户名、密码和确认密码。这个要记好，后面连接到这个Database的时候会用得到。

### Networking

- Network connectivity: 选择了`Public access`。暂时没必要配置`VNet`。
- Public access：开启了 `Allow public access to this resource through the internet using a public IP address`，方便我进行调试等操作。
- Firewall rules：开启了`Allow public access from any Azure service within Azure to this server`。这样我后端访问会方便很多，没必要为后端单独配置。另外，我直接点击了下面的`Add current client IP address`，这样我本机可以直接访问这个Database，方便开发阶段进行调试等。如果后面有其他服务也需要访问这个Database，可能会需要在此处配置IP address。
- Private endpoints：由于我没有设置什么VNet，因此此处为空。

### Security

- Data encryption: 选择了`Service-managed key`。如果选`Customer-*`则是自己上传的key。我理解是此处涉及到数据加密，如果有保密需求可以考虑下面的。

### Tags

- Tags：此处可以添加一些标签，方便后续管理。我这里添加了`owner`和`project`两个标签。按自己需求添加即可。

---

全部完成之后，进入 *Review + Create* 页面，确认无误即可点击 Create 完成创建。


## Database Connection

完成之后，接下来就需要进行连接测试，保证我们的Dataset正常运行。我的测试主要分为两个步骤，首先使用一些直接连接数据库的应用进行测试，然后直接修改本地后端部分的接口，进行数据库的连接测试。

为此，我们需要先找到刚才创建的Database的Service。在`Endpoint`部分，可以看到这个Database的URL：

```txt
[YourServiceName].postgres.database.azure.com
```

为了验证数据库可以成功运行，可以使用一些工具来进行数据库的管理。可以通过Azure Portal下面的*Getting started*部分查看一些教程，里面会有详细的连接数据库的流程。

我尝试了两种方法：

- 使用pgAdmin。这是图形化的界面的管理数据库的软件，下载之后按照流程连接即可。记得要开启SSL（`sslmode=require`），否则会报错`no encryption`。
- 使用VSCode中的postgresql。

> 值得注意的是，VSCode的插件一次只能连接一个数据库。连接的时候需要在第6步（The database to connect to）选择希望访问的数据库，否则没办法看到这个数据库下面的表。
{: .prompt-warning }

我使用的是pgAdmin来进行连接，创建了相应的Database，而VSCode的插件仅用于读取和debug。这两步测试完成后，我便通过自己的Python程序进行Database的连接测试。

此处附上我相应的Python代码：

```Python
DATABASE_URL = "postgresql+psycopg2://[YourAdminUserName]:[YourAdminPassword]@[YourServiceURL]:[PortNum]/[CreatedDatabaseName]?sslmode=require"

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine(DATABASE_URL, echo=False)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
db = SessionLocal()

# Some code here (db.add(), db.commit(), etc.)
```

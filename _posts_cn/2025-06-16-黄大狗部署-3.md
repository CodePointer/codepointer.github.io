## 前言 Introduction

我的APP主要包含三个部分的内容：数据库（Database），后端（Backend），前端（Frontend）。这三个部分都需要部署到Azure上，同时价格需要尽可能低廉，能白嫖就要白嫖。

对于后端部分，我准备使用的是 `Azure Functions App`。我的后端架构为Python FastAPI，这个框架可以直接被转化为适用于 Function App 的形式。

下面的部分假设已经注册了Azure的账户，已经可以登录到Azure Portal。

## Service Creation

搜索选择 `Service` 下面的 `Function App`。选择Create之后，按照提示填写信息。以下是每一项的说明和我填写的内容。

### Basics

- Project details, Subscription & Resource group: 创建的这个Service的分组。Subscription应该和Azure的付费有关，而Resource group则是自己给的一个分组。我这里直接选择了在Database中创建的Resource group。

- Function App name: 应用的名字。起一个自己需要的名字即可。
- Region：服务器所在的位置。考虑到我这个应用主要使用的区域可能是中国和澳大利亚，因此我选择了东南亚 (Southeast Asia) 作为服务器的位置。
- Runtime stack：选择 `Python`。因为我后端使用的是FastAPI。
- Version: 选择 `3.10`。此处选择和后端一致的版本即可。有资料建议Azure Function App的版本最好固定选择`3.10`。
- Instance size: 我选择了`2048 Mb`。
- Zone redundancy: 我选择了`Disabled`。穷鬼套只能选这个。

### Storage

- Storage account: 此处应该有一个自动的名字，不用管它。
- Diagnostic Settings：此处我选择了`Don't configure diagnostic settings now`。后面也可以再打开，短时间内暂时不太需要看这个日志。

### Azure OpenAI

由于我此处并不需要Azure内置的OpenAI服务，因此我没有勾选这个选项。即便我们APP中会包含有OpenAI的resource，但如果不是从Azure订阅的，此处就不需要配置。

### Networking

- Enable public access: 我选择了`On`，因为测试的时候还是会需要从本地前端访问这个Service。
- Enable virtual network integration: 我选择了`Off`。因为我没有配置VNet，因此此处暂时不需要配置。

### Monitoring

- Enable Application Insights: 我选择了`Off`。但此处我会建议打开。事实上我后面在Debug这个Function的时候也手动把它打开了。设置Application Insights等价于设置一个新的Service，但这个新的Service就是服务于log的。因此我还是建议开启这个选项。但此处设置为`Off`后，后面手动开启也是一样的。

### Deployment

- Continuous deployment: 我选择了`On`。因为我会需要使用Github进行代码的部署。
- Github settings：此处连接到自己的Github账户，然后选择Organization、Repository和Branch即可。
- Basic authentication: 我选择了`Off`。因为我没有设置Github的Basic authentication，因此此处不需要开启。

> 有需要的话，可以preview一下创建的`.yml`文件，但也可以先不管，反正后面生成的模板都是要改的。
{: .prompt-info }

### Authentication

此部分我没有做修改，均为默认的选项。

### Tags

- Tags：此处可以添加一些标签，方便后续管理。我这里添加了`owner`和`project`两个标签。按自己需求添加即可。

---

全部完成之后，在 *Review + Create* 界面确认自己的信息。确认无误的话可以直接点 Create。


## Modifying FastAPI to Function

为了将FastAPI部署到Azure Function App，我们需要对FastAPI进行一些修改。具体内容可以参考Azure的官方文档：[Using FastAPI Framework with Azure Functions](https://learn.microsoft.com/en-us/samples/azure-samples/fastapi-on-azure-functions/fastapi-on-azure-functions/)。

这里给出我做的修改步骤。首先，需要在`requirements.txt`中新增新的依赖：

```json
// backends/requirements.txt
...
azure-functions
...
```

完成之后，需要新增以下三个文件：

- `backend/host.json`
- `backend/HttpTrigger/function.json`
- `backend/HttpTrigger/__init__.py`

三个文件的内容如下：

```json
// backend/host.json
{
  "version": "2.0",
  "logging": {
    "applicationInsights": {
      "samplingSettings": {
        "isEnabled": true,
        "excludedTypes": "Request"
      }
    }
  },
  "extensionBundle": {
    "id": "Microsoft.Azure.Functions.ExtensionBundle",
    "version": "[4.0.0, 5.0.0)"
  },
  "extensions": {
    "http": {
      "routePrefix": ""
    }
  }
}
```

```json
// backend/HttpTrigger/function.json
{
  "bindings": [
    {
      "authLevel": "anonymous",
      "type": "httpTrigger",
      "direction": "in",
      "name": "req",
      "route": "{*segment}",
      "methods": ["GET", "POST", "PUT", "DELETE", "PATCH", "OPTIONS"]
    },
    {
      "type": "http",
      "direction": "out",
      "name": "$return"
    }
  ],
  "scriptFile": "__init__.py"
}
```

```python
# backend/HttpTrigger/__init__.py

import azure.functions as func
from azure.functions import AsgiMiddleware
from app.main import app  # Your FastAPI app instance

asgi_app = AsgiMiddleware(app, http)

def main(req: func.HttpRequest, context: func.Context) -> func.HttpResponse:
    return asgi_app.handle(req, context)
```

添加以上操作后，我们就可以把FastAPI部署到Azure Function App了。成功部署之后，应该可以在该 Function App 的页面中看到 HttpTrigger 一项。


## Github Workflow

在设置好Function App后，如果成功链接了Github，会在`.github/workflows`下生成一个模板文件：

```yml
# Template

name: Build and deploy Python project to Azure Function App - [YourServiceName]

on:
  push:
    branches:
      - main
  workflow_dispatch:

env:
  AZURE_FUNCTIONAPP_PACKAGE_PATH: '.' # set this to the path to your web app project, defaults to the repository root
  PYTHON_VERSION: '3.10' # set this to the python version to use (supports 3.6, 3.7, 3.8)

jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read #This is required for actions/checkout

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Python version
        uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}

      - name: Create and start virtual environment
        run: |
          python -m venv venv
          source venv/bin/activate

      - name: Install dependencies
        run: pip install -r requirements.txt

      # Optional: Add step to run tests here

      - name: Zip artifact for deployment
        run: zip release.zip ./* -r

      - name: Upload artifact for deployment job
        uses: actions/upload-artifact@v4
        with:
          name: python-app
          path: |
            release.zip
            !venv/

  deploy:
    runs-on: ubuntu-latest
    needs: build
    permissions:
      id-token: write #This is required for requesting the JWT
      contents: read #This is required for actions/checkout

    steps:
      - name: Download artifact from build job
        uses: actions/download-artifact@v4
        with:
          name: python-app

      - name: Unzip artifact for deployment
        run: unzip release.zip     
        
      - name: Login to Azure
        uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZUREAPPSERVICE_CLIENTID_??? }}
          tenant-id: ${{ secrets.AZUREAPPSERVICE_TENANTID_??? }}
          subscription-id: ${{ secrets.AZUREAPPSERVICE_SUBSCRIPTIONID_??? }}

      - name: 'Deploy to Azure Functions'
        uses: Azure/functions-action@v1
        id: deploy-to-function
        with:
          app-name: '[YourServiceName]'
          slot-name: 'Production'
          package: ${{ env.AZURE_FUNCTIONAPP_PACKAGE_PATH }}
```

但由于我代码结构有所不同，原模板文件并不能直接使用。在我的项目中，前端和后端的代码都存在同一个repository下面，分别在`~/frontend`和`~/backend`目录下。同时，我代码中暂时不存在test的部分，所以也不用进行代码的build。因此我对于原本的模板文件进行了修改和简化。以下附上我所使用的yml文件。

```yml
# .github/workflows/deploy-backend.yml

name: Build and Deploy backend to Azure Functions

on:
  push:
    branches: [ main ]
    paths:
      - 'backend/**'  # Only work on backend code
      - '.github/workflows/deploy-backend.yml'  
  workflow_dispatch:

env:
  AZURE_FUNCTIONAPP_PATH: './backend'

permissions:
  id-token: write # Required for requesting the JWT
  contents: read # Required for actions/checkout

jobs:
  deploy:
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.10'

      - name: Login to Azure
        uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZUREAPPSERVICE_CLIENTID_XXX }}
          tenant-id: ${{ secrets.AZUREAPPSERVICE_TENANTID_XXX }}
          subscription-id: ${{ secrets.AZUREAPPSERVICE_SUBSCRIPTIONID_XXX }}
                
      - name: Deploy to Azure Functions
        uses: Azure/functions-action@v1
        with:
          app-name: '[MyServiceName]'
          slot-name: 'Production'
          package: ${{ env.AZURE_FUNCTIONAPP_PATH }}
          sku: 'flexconsumption'
          remote-build: true
```

> 重点：此处workflow并不负责build，而是直接将代码推送到Azure Function App中。因此，需要保证Azure Function App会进行build操作。具体的操作是需要在最后一个步骤中加入`sku: 'flexconsumption`和`remote-build: true`两个参数，两个参数都需要。flexconsumption似乎对于免费版的Azure Function App而言是必须的。具体参考网址可以看 [这里](https://stackoverflow.com/questions/79513001/successful-github-actions-workflow-does-not-deploy-python-app-to-azure-function)。
{: .prompt-warning }


## CORS Setting

在Azure Function App中，默认情况下，CORS设置是关闭的。因此需要在CORS的设置中开启，将浏览器访问时候的域名添加到CORS下。例如，我添加的网址为：

```python
# Assuming port is 1234

# For development
http://localhost:1234
http://192.168.1.128:1234

# For production
https://mrginger.top
https://www.mrginger.top
```

值得注意的是，FastAPI自己代码中的CORS与这里是独立的。但根据测试，FastAPI内部的CORS会被关闭，只需要设置Azure这里就可以。(是的，前面我那么费劲的设置该环境变量的解析，这里其实用不到)


## Environmental Variables

环境变量我使用Azure来进行管理。在Panel中进行设置即可。由于在代码中环境变量是通过读取`.env`进行的，而在production时没有这个文件，代码就会从运行环境中读取。在Azure中设置即可保证正确的运行。

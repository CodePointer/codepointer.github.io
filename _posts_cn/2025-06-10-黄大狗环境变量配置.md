## 前言 Introduction

### 背景 Background

我的前端和后端程序在开发过程中和生产过程中存在一些变量上的差异。

例如，我会有专门用于测试用的数据库，以及测试过程中前端连接的后端、后端连接的数据库都与真正上线时候所用的不同。因此，有一些变量是需要能够自动从环境中读取的。

因此，我需要为我的前端和后端软件配置相应的环境变量。本以为配置环境变量是个蛮简单的事，没想到做起来却遇到了很多的坑，内容非常值得单独开一期博客记录一下。

### 需求 Requirements

我需要为我的前端和后端程序分别配置相应的环境变量组，这样才方便我进行开发。因为开发时候我可能是单独开发前端或是后端，此时会需要连接不同的其它Service。

我的前端平台是Expo Router，而后端平台为Fast API。

另外，这个环境变量必须能够自动选择。代码上线之后可以直接使用production版本，不需要每次手动更改；而在本地我可以方便的切换development和production版本，方便进行开发和基础测试。

### Solutions

考虑我的需求，最终决定使用下面两种方式进行环境变量的管理：

1. 对于backend，使用`Pydantic v2 (pydantic-settings)`进行管理，同时使用`.env.[development/production]`文件进行本地变量的管理。

2. 对于frontend，使用Expo CLI内置的环境变量支持。同时使用一个带有`NODE_ENV`的`.env`文件，以及`.env.[development/production]`进行不同环境变量的管理和导入。

3. 以上环境变量均用于本地的开发过程。部署时，相应的环境变量录入到Azure平台或是Github平台中。

## Backend: Pydantic v2 (pydantic-settings)

在我的后端代码中，我会涉及到以下几个环境变量：

```ini
SECRET_KEY="SOMESECRETKEYHERE"  # Key for JWT
ALGORITHM="XXX"
DATABASE_URL=http://myadminname:mypassword@localhost:5432/mydatabase
ACCESS_TOKEN_EXPIRE_MINUTES=1440  # 24 * 60
RESET_TOKEN_EXPIRE_MINUTES=720
CORS_ORIGINS=http://localhost:8081,http://192.168.1.128:8081
```

可以看到其中大部分是`string`或是`int`类型，但`CORS_ORIGINS`是一个由多个url地址组成的`list`类型。我会需要在代码中对这部分进行解析。

为此，我准备使用`Pydantic v2`进行环境变量的管理。首先需要安装相应的环境，记得要在`requirements.txt`中增加以下内容：

```txt
pydantic>=2.0
pydantic-settings
```

> 需要注意的是对于`Pydantic v2`，和Settings相关的东西被移到了`pydantic-settings`包中。因此，我需要额外安装`pydantic-settings`包。
{: .prompt-warning }

装完之后，就可以定义`Settings`这个变量了：

```python
# backend/app/core/config.py

import os
from pydantic_settings import BaseSettings, SettingsConfigDict
from pydantic import Field

class Settings(BaseSettings):
    SECRET_KEY: str
    ALGORITHM: str
    DATABASE_URL: str
    ACCESS_TOKEN_EXPIRE_MINUTES: int
    RESET_TOKEN_EXPIRE_MINUTES: int

    model_config = SettingsConfigDict(
        env_file = f".env.{os.getenv('APP_ENV', 'development')}",
        env_file_encoding="utf-8"
    )

settings = Settings()
```

经过以上设置，除了`CORS_ORIGINS`之外的所有变量都可以成功解析了。同时如果要切换`development`和`production`，只需要分别创建好两个`.env.development`文件和`.env.production`文件，通过指定`APP_ENV`环境变量来进行切换就可以。

但是由于`CORS_ORIGINS`是一个`list`类型，因此在解析这个变量的时候出现了很多错误。

### `list[*]`类型环境变量解析

为了需要解析`list`类型，有两种方案。

**方案1：使用 JSON 数组格式进行解析**

可以在`.env.*`中写入合法的 JSON 格式：

```python
# backend/.env.*
CORS_ORIGINS=["http://localhost:8081","http://192.168.1.128:8081"]


# backend/app/core/config.py
class Settings(BaseSettings):
    ...
    CORS_ORIGINS: list[str]
    ...
```

这是由于 Pydantic 默认行为就是使用 JSON 格式进行解析的。但环境变量的内容有点冗长，转义引号和括号都需要包裹进来。如果就希望使用简单的逗号分隔方式，或是更为复杂的解析方式，则需要使用另一种方案。

**方案2：自定义中间属性+解析**

定义一个中间字段`RAW_CORS_ORIGINS`，再通过 Validator 拆分。

```python
# backend/.env.*
CORS_ORIGINS=http://localhost:8081,http://192.168.1.128:8081


# backend/app/core/config.py
class Settings(BaseSettings):
    ...
    RAW_CORS_ORIGINS: str = Field("", alias="CORS_ORIGINS")
    
    @property
    def CORS_ORIGINS(self):
        return [u.strip() for u in self.RAW_CORS_ORIGINS.split(",") if u.strip()]
    ...
```

这样的好处是可以自定义解析过程，并且环境变量的格式会更简单一些。

> 部分不可行的小坑：
>
> - 使用 `@field_validator` 或是 `@model_validator` 等校验逻辑：不可行。
>   - Pydantic是在所有原始值加载完成之后才进入 `@*_validator` 的校验逻辑。因此，如果在 Source 阶段解析失败抛出了 `JSONDecodeError`，就会直接终止加载并报错了，`@*_validator`并没有作用。
> - 使用`Field(..., env=None)`阻止对`list[...]`字段进行JSON解析，从而后面使用`@*_validator`进行校验：不可行
>   - 至少在 Pydantic v2 中，加了这个参数没用，不能阻止`DotEnvSettingsSource` 对 `list[...]` 字段做 JSON 解析。
> - 使用`env="CORS_ORIGINS"`进行变量与环境变量的对应：不可行
>   - 在 v2 中，该变量变为了 `alias="CORS_ORIGINS"`。很多资料（尤其是AI给的）都是基于 v1 的，这里会出错误。
{: .prompt-warning }

总之，我最后选择了**方案二**。我这部分的代码总体如下：

```python
# backend/app/core/config.py

import os
from pydantic_settings import BaseSettings, SettingsConfigDict
from pydantic import Field


class Settings(BaseSettings):
    SECRET_KEY: str
    ALGORITHM: str
    DATABASE_URL: str
    ACCESS_TOKEN_EXPIRE_MINUTES: int
    RESET_TOKEN_EXPIRE_MINUTES: int
    RAW_CORS_ORIGINS: str = Field("", alias="CORS_ORIGINS")

    @property
    def CORS_ORIGINS(self):
        return [u.strip() for u in self.RAW_CORS_ORIGINS.split(",") if u.strip()]
    
    model_config = SettingsConfigDict(
        env_file = f".env.{os.getenv('APP_ENV', 'development')}",
        env_file_encoding="utf-8"
    )


settings = Settings()
```

而在使用中，则直接调用`settings`这个对象即可拿到相应的环境变量。比如说：

```python
# backend/app/main.py
from fastapi import FastAPI
from app.core.config import settings

app = FastAPI(title="Mr.Gingerpaw API")
app.add_middleware(
    ...
    allow_origins=settings.CORS_ORIGINS,
    ...
)
```


## Frontend: Expo CLI内置的环境变量支持

由于我的 SDK 为 53.0，所以 Expo CLI 可以使用 `NODE_ENV` 进行自动环境变量加载了。具体来说，我会需要有以下几个文件：

```ini
# frontend/.env
NODE_ENV=development

# frontend/.env.development
EXPO_PUBLIC_API_BASE_URL=http://127.0.0.1:8000

# frontend/.env.production
EXPO_PUBLIC_API_BASE_URL=https://[MyServiceName].azurewebsites.net
```

我可以通过设置`NODE_ENV`的值，直接进行两个环境的切换。需要注意的是变量名必须以`EXPO_PUBLIC_*`开头，否则变量不会内联到代码中。

> 不能使用 `react-native-dotenv` 插件。如果使用了的话，它会直接覆盖 Expo Router 的 Babel 自动配置，导致 Expo CLI 无法检测`app/`目录下面的路由，于是表现为它只会显示默认的 "Welcome to Expo" 页面。
{: .prompt-warning }

完成上述设置，在代码中可以直接使用以下方式访问定义好的环境变量：

```js
// frontend/services/utils/axioInstance.ts
const API_BASE_URL = process.env.EXPO_PUBLIC_API_BASE_URL;
```

## Summary

- 对于后端，我们使用`Pydantic v2 (pydantic-settings)`进行管理，同时使用`.env.[development/production]`文件进行本地变量的管理。
  - 对于`string`或是`int`类型可以直接进行定义，而`list`类型则需要符合 JSON 解析格式。
  - 如果不希望使用 JSON 进行变量解析，则需要自定义中间属性 + `@property` 方式进行解析。

- 对于前端，我们使用Expo CLI内置的环境变量支持。同时使用一个带有`NODE_ENV`的`.env`文件，以及`.env.[development/production]`进行不同环境变量的管理和导入。
  - 不可以使用 `react-native-dotenv` 插件，与 Expo Router 不兼容。

以上！

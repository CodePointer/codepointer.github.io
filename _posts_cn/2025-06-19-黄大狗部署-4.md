## 前言 Introduction

我的APP主要包含三个部分的内容：数据库（Database），后端（Backend），前端（Frontend）。这三个部分都需要部署到Azure上，同时价格需要尽可能低廉，能白嫖就要白嫖。

对于前端部分，我准备使用 `Azure Static Web Apps`，该服务可以托管静态网站，免费额度非常多，基本不用另外花钱。

下面的部分假设已经注册了Azure的账户，已经可以登录到Azure Portal。

## Service Creation

搜索选择 `Service` 下面的 `Azure Static Web Apps`。选择Create之后，按照提示填写信息。以下是每一项的说明和我填写的内容。

### Basics

- Project details, Subscription & Resource group: 创建的这个Service的分组。Subscription应该和Azure的付费有关，而Resource group则是自己给的一个分组。同样的，把我Frontend放在了和数据库、后端在一起的Resource group里面。

- Hosting region 不用选，自动是Global。

- Static Web App details - Name: 选一个自己的名字即可。

- Hosting plan：选 Free即可。

- Deployment details: 选择了Github之后，会需要设置Organization、Repository和Branch。

- Build Presets: 需要注意的是我们虽然前端平台使用的是React，但我们准备把代码build之后直接发布静态的site。因此，此处的Preset应该选择`Custom`。

- App location：这里实际指的是我们代码build之后出来的静态site所在的文件夹。因此，此处可以填写`./frontend/dist`。

- Api location & Output location：这两个可以为空，因为我们的build是在Github上面完成的。

### Deployment Configuration

- Deployment authorization policy: 此处选择Github。

### Advanced & Tags

- Region for Azure Functions API and staging environments: 由于我们后端设在了东南亚，因此此处我们选择了最近的`East Asia`。
- Enterprise-grade edge: 穷鬼套选不了。
- Tags还是自己设置。

---

全部完成后，还是在 *Review + Create* 页面检查一遍，无误后点击 Create。

## Github Workflow

在我们的Service里面链接了Github之后，`.github/workflow`文件夹下面就会多出一个`.yml`文件。这个`.yml`文件的文件名在Service的Overview页面也能看到，我们接下来就需要修改这个文件。

> 重点：这个yml文件不能重命名。比方说默认名字是`azure-static-web-apps-mango-sand-xxx.yml`，那这个名字是不能改的，只能改里面的内容，否则一定没法成功deploy。这个问题2021年就有人提问了，但直到今天还没有解决。具体参考网址可以看 [这里](https://stackoverflow.com/questions/67389728/how-can-i-change-the-workflows-yml-file-in-an-azure-static-web-app)。
{: .prompt-warning }

另外，由于我们需要自己build相应的代码，因此比起模板的直接push，此处还会涉及到build的部分。以下是我所使用的`.yml`文件，供参考：

```yml
# .github/workflows/azure-static-web-apps-thankful-cliff-xxx.yml

name: Build and Deploy frontend to Azure Static Web Apps

on:
  push:
    branches: [ main ]
    paths:
      - 'frontend/**'
      - '.github/workflows/azure-static-web-apps-thankful-cliff-xxx.yml'
  workflow_dispatch:

permissions:
  id-token: write # Required for requesting the JWT
  contents: read # Required for actions/checkout

jobs:
  build_and_deploy:
    runs-on: ubuntu-latest
    env:
      EXPO_PUBLIC_API_BASE_URL: ${{ secrets.EXPO_PUBLIC_API_BASE_URL }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v3
        with:
          submodules: true
          lfs: false

      - name: Install OIDC Client from Core Package
        run: npm install @actions/core@1.6.0 @actions/http-client
      - name: Get Id Token
        uses: actions/github-script@v6
        id: idtoken
        with:
           script: |
               const coredemo = require('@actions/core')
               return await coredemo.getIDToken()
           result-encoding: string

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '22.x'

      - name: Install dependencies
        run: |
          cd frontend
          npm ci

      - name: Build Expo Web
        run: |
          cd frontend
          npx expo export --platform web

      - name: Deploy to Azure Static Web Apps
        id: builddeploy
        uses: Azure/static-web-apps-deploy@v1
        with:
          azure_static_web_apps_api_token: ${{ secrets.AZURE_STATIC_WEB_APPS_API_TOKEN_THANKFUL_CLIFF_xxx }}
          action: "upload"
          app_location: "./frontend/dist" # App source code path
          api_location: "" # Api source code path - optional
          output_location: "" # Built app content directory - optional
          github_id_token: ${{ steps.idtoken.outputs.result }}
          skip_app_build: true # Skip the app build step since we already built it with Expo
```

## 绑定自定义域名

在 Namesilo 上购买了域名后，需要在托管的 Cloudflare 中设置好相应的 DNS。Azure推荐使用 CNAME 的方式进行设置。设置好后，需要到前端的界面中进行Validation，这样才能让https正常访问。

> 否则会提示证书错误。
{: .prompt-tip }

> 更新之后，DNS应该很快就会刷新。但我家使用的是Opticomm，DNS刷新特别特别慢，体感大概需要24小时甚至48小时以上。
{: .prompt-warning }

## Backend CORS设置

最后，虽然CORS设置的部分是后端的内容，但前端成功上线之后，我们需要后端对前端的app地址放行，因此记得要去后端设置对应的CORS才能让前端调用。
